# Documented Deviations from Pre-Registration (`configs/prereg.yaml`)

This document records every deviation from `configs/prereg.yaml` and `proposal/proposal.tex`, together with its technical rationale and exact code location, committed prior to running the pilot or any main experiments (`audit/GUARDIAN_B1_code.md`, `audit/AGY_TASK_B2_fixes_pilot.md`).

---

## Summary Table of Deviations

| ID | Category | Pre-Registered (`configs/prereg.yaml`) | Deviation | Reason | Code / Config Locations |
|---|---|---|---|---|---|
| **D-1** | `always_fresh` terminology & Test 2 | `always_fresh` listed under `bounds`; Test 2 asserted `missed_neighbors(always_fresh) <= missed_neighbors(rule)` for every budgeted rule. | Call `always_fresh` a **reference** (`REFERENCE_POLICIES`), not a bound. Replace Test 2 with a structural test verifying that `always_fresh` refreshes and publishes all $S$ summaries before each epoch's queries, plus an `oracle_routing` bound check. | 16-center max-dot-product summaries are heuristic routing approximations; fresh k-means centers can occasionally route slightly worse than stale centers on individual seeds (`Guardian H-1`, seeds 44 and 47). | `dvs/policies.py`, `dvs/run.py`, `tests/test_simulator.py`, `docs/DESIGN.md` |
| **D-2** | Reference policies (`never_refresh`, `oracle_routing`) | Only `always_fresh` and `all_shards` included as unbudgeted comparisons. | Add two unbudgeted references reported for context: `never_refresh` (published summaries never change after setup) and `oracle_routing` (routes each query to the $m$ shards holding the most ground-truth top-10 neighbors). | `never_refresh` measures the zero-refresh baseline (defining the refresh headroom `always_fresh - never_refresh`), while `oracle_routing` provides the true $m$-shard routing upper bound (`Guardian H-1, H-2`). | `dvs/policies.py`, `dvs/coordinator.py`, `dvs/run.py`, `tests/test_simulator.py` |
| **D-3** | Spearman correlation when undefined | `compute_spearman_correlation` returned `0.0` on constant/undefined inputs and averaged those zeros into `spearman_rho_mean`. | Return `NaN` (`float("nan")`) when Spearman correlation is undefined, skip `NaN` when computing `spearman_rho_mean`, and report `spearman_n_defined` in `summary.json`. | Mapping undefined rank correlations (e.g., when all shards have zero lift-in flips) to `0.0` artificially biases the mean correlation toward zero (`Guardian M-1`). | `dvs/metrics.py`, `dvs/run.py`, `tests/test_simulator.py` |
| **D-4** | CPU timing isolation | `compute_recovered_neighbor_raw_scores` ran inside the `policy` timer for all refresh rules; `gt.add` ran inside the `insert` timer. | Charge the recovered-neighbor estimate (`compute_recovered_neighbor_raw_scores`) only to `recovered_neighbor`. Time ground-truth work (`gt.add`, `gt.search`, `compute_true_recovered_neighbors_per_shard`) separately in `cpu_ground_truth_s` and exclude it from method CPU (`cpu_total_s`). | Non-RN policies do not run sample-query probing in deployment, and exact ground-truth maintenance/evaluation is harness overhead rather than method CPU (`Guardian M-2`). | `dvs/metrics.py`, `dvs/policies.py`, `dvs/run.py`, `tests/test_simulator.py` |
| **D-5** | Setup-cost charging condition & amortized byte total | `configs/exp5_reference_checks.yaml` mixed `charge_setup_to_budget: true` with `sharding_mode: hash` and `bursts: true`; `epoch_budget_bytes_with_amortized_setup` double-counted amortized setup bytes when `charge_setup_to_budget=True`. | Run `charge_setup_to_budget: true` as its own single-factor condition (only that change vs. the default). Fix `ByteBus.epoch_budget_bytes_with_amortized_setup` so it does not add amortized setup bytes a second time when already charged to the epoch budget. Include all condition flags in `run_id`. | Mixing three changes prevents isolating the effect of setup-cost charging, and adding amortized setup bytes on top of an already-charged setup message double-counted the setup cost (`Guardian M-3, M-4, L-5`). | `dvs/bus.py`, `dvs/run.py`, `configs/exp1_steady.yaml`, `configs/exp2_cluster_order.yaml`, `configs/exp3_query_shift.yaml`, `configs/exp5_reference_checks.yaml`, `tests/test_simulator.py` |
| **D-6** | Starvation cap ($A = 8$ epochs) vs. additive aging | Added $+0.5 \times \text{epochs\_waited}$ to each rule's $[0, 1]$-scaled score. | Replace additive aging for all refresh rules with a starvation cap $A = 8$ epochs (`aging_mode="starvation_cap"`): any shard with unrefreshed vectors that has waited more than $A = 8$ epochs (`epochs_since_refresh > 8`) is refreshed first (ties broken by the rule's score); otherwise shards are ranked purely by the rule's score. Keep additive $+0.5$/epoch aging available as `aging_mode="additive"` for sensitivity checks. | Additive $+0.5$/epoch swamps scores in $[0, 1]$ whenever ages differ by $\ge 2$ epochs, forcing all rules into near-round-robin order (`Guardian M-5`). | `dvs/policies.py`, `dvs/run.py`, `tests/test_simulator.py` |
| **D-7** | `new_topic` arrival stream & pilot headroom gate | Streams (`steady`, `cluster_order`, `query_shift`) used a uniform random 50,000 / 50,000 initial/stream split. | Add `new_topic` in `dvs/streams.py`: run 64-cluster spherical `faiss.Kmeans` (fixed seed) on all 100,000 vectors, place clusters in a seeded random order, use the first 32 clusters as the initial set (`47,273` vectors at seed 42) and stream the other 32 clusters (`52,727` vectors at seed 42) cluster by cluster. Build initial shards and summaries only from the initial set; route new vectors to the nearest initial center. Run a pilot (`steady` and `new_topic`, 1 seed, $S=32, m=2, c=16, Q=200, B=4$) with gate $\text{GATE} = \text{recent\_recall@10}(\text{always\_fresh}) - \text{recent\_recall@10}(\text{never\_refresh})$ on `new_topic` ($\ge 0.05$ required for main runs on `new_topic`). Keep `steady` and `cluster_order` unchanged. | Under a random 50,000/50,000 split, initial summaries already cover all 64 clusters and shard regions remain stationary, leaving $< 2.6$ points of recent-recall headroom between `never_refresh` and `always_fresh` (`Guardian H-2`). | `dvs/streams.py`, `dvs/run.py`, `configs/pilot.yaml`, `tests/test_simulator.py` |
| **D-8** | Implementation specifics documented from B1 | Implicit in `proposal/proposal.tex`. | Document: (a) refresh rules prioritize shards with `num_new_vectors > 0` before shards with 0 new vectors (`round_robin` still advances its cursor by `num_summaries_to_send`); (b) `ql` and `ss` rank shards by past top-$m$ popularity and shard size to pick whole summaries each epoch; (c) `extra_search` ranks $(m, m+1)$ score gaps across the current epoch's query batch; (d) `missed_neighbors` excludes vectors already pushed to the coordinator under `push_vectors`; (e) `chroma-hnswlib` provides the `hnswlib` module. | Ensures full reproducibility and transparency of implementation choices noted in `Guardian L-1, L-2`. | `docs/DESIGN.md`, `docs/DEVIATIONS.md` |
