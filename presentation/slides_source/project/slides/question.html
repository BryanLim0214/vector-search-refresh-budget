The question

Where should the network bytes go?

Each method with a budget may send the same number of bytes each time step: the size of 2, 4 or 8 summaries. The default, 4 summaries, is 98,304 bytes.

Refresh

A shard sends the coordinator a fresh summary of what it now holds.

24,576 bytes per summary

Extra search

When the coordinator is unsure, the question also goes to a third shard.

1,656 bytes per extra search

Push

Shards send copies of their newest passages, and the coordinator checks them for every question.

1,544 bytes per passage

And if we refresh, which shards should go first? We compare five rules, one of them our own.

About 45 seconds So the system has a fixed allowance of network bytes each time step, and every method that has a budget gets exactly the same allowance. That keeps the comparison fair. There are three ways to spend it, shown in the three small animations. Refresh: a shard sends the coordinator a fresh summary of what it now holds. Extra search: when the coordinator is unsure which shards hold the answer, the question also goes to a third shard. Push: shards send copies of their newest passages, and the coordinator checks those copies for every question. The second question is about refreshing itself. If we can only refresh a few shards each step, which ones should go first? We compare five rules, and one of them is our own.
