The problem

Summaries go out of date

A vector database finds the stored passages that are closest in meaning to a question.

Ours keeps 100,000 passages on 32 servers, called shards. A coordinator, like a front desk, sends each question to only 2 shards. It chooses them from a short summary of each shard: 16 points that mark the main topics the shard holds.

New passages keep arriving, but the coordinator uses each shard’s old summary until the shard sends a fresh one. A question can then miss a good new match.

About 50 seconds First, what is a vector database? It stores passages of text as lists of numbers that capture their meaning. When a question comes in, it finds the stored passages whose meaning is closest. Ours keeps one hundred thousand passages on thirty-two servers, which we call shards. To save work, a coordinator, which works like a front desk, sends each question to only two shards. It decides which two by looking at a short summary of every shard: sixteen points that mark the main topics the shard holds. Here is the problem, in the animation. New passages land on shard three. But the coordinator still has shard three’s old summary, so it sends the question to shards one and two and misses the new match. Once shard three sends a fresh summary, the question goes to shard three and finds it. Fresh summaries help, but each one means more bytes sent over the network.
