What we built

One simulated time step

At the start, about half of the passages are split into 32 shards by similarity of meaning. Each shard builds its own fast search structure and its 16-point summary. Then 50 time steps follow, each like this:

1

New passages arrive

About 1,000 per step. A placement rule picks each one’s shard.

2

True answers found

A slow, exact search over everything finds each test question’s real best matches, so answers can be graded.

3

Summaries prepared

Each shard that changed computes a fresh summary but does not send it yet.

4

The budget is spent

On refreshes, extra searches, pushed copies or sample questions. Every message’s bytes are counted.

5

Questions answered

Each goes to 2 shards, plus any extra search and pushed copies. The best 10 results are kept.

6

Graded against the truth

The run stops if a budgeted method spends more than its share.

Scope: everything runs on one computer. Bytes are counted exactly, but network delay, waiting in line and server failures are not modeled.

How the simulator works

About 50 seconds This is the simulator I built, shown as one time step. At the start, about half of the passages are split into thirty-two shards by similarity of meaning, and every shard builds its own fast search structure and its summary. Then each of the fifty time steps goes the same way. New passages arrive, about a thousand per step, and a placement rule decides which shard stores each one. A slow, exact search over everything finds the true best answers, so we can grade every answer. Shards that changed prepare a fresh summary but do not send it yet. Then the method spends its byte budget, and every message is counted with its size. Questions are answered from two shards plus whatever extra the method paid for. Finally every answer is graded against the truth, and the run stops if a method overspends. One honest limit: it all runs on one computer. We count bytes exactly, but we do not model network delay, waiting in line, or failures. This slide covers the architecture part of the rubric.
